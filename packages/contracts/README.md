# packages/contracts

The OpenAPI spec `services/api` actually serves, and the TypeScript types generated from it (docs/TASKS.md T11). Neither file is ever hand-edited — both are generated, committed, and drift-checked in CI so they can never silently go stale (docs/API_CONTRACT.md, "Contract governance"; docs/DECISIONS.md ADR-033).

- `openapi.json` — generated by `services/api`'s `OpenApiSpecGenerator` (a Testcontainers-backed test that fetches the real, running application's `/v3/api-docs`), never hand-written ahead of the implementation.
- `src/schema.d.ts` — generated from `openapi.json` by [`openapi-typescript`](https://openapi-ts.dev).

## Regenerating after a backend change

```bash
make generate-contracts   # from the repo root — needs Docker (Gate H0)
```

Review the diff and commit it. `apps/web/src/lib/api/client.ts` is the one place the typed client (`openapi-fetch` + these generated types, imported via the `@contracts/*` path alias in `apps/web/tsconfig.json`) is actually constructed; every other `apps/web/src/lib/api/*.ts` file calls through it.

## Drift check

```bash
make test-contract   # from the repo root — needs Docker (Gate H0)
```

Runs both halves: `services/api`'s `OpenApiSpecDriftTest` (fails if the committed spec no longer matches the real endpoints) and `scripts/check-schema-drift.sh` (fails if `src/schema.d.ts` no longer matches the committed `openapi.json`). Both run in CI on every push.
